# Pricing strategies

`commerce.billing.pricing-strategies` holds **pricing strategies** by name. A strategy turns a
period's recorded usage into a charge in fractional USD. It says which input it consumes (`'cost'`
or `'quantity'`) and prices it with `price($providerCostUsd, $quantity, $params)`. A billing
component that charges for metered usage reads the strategy name from its config and resolves it
here, so each meter can price itself by its own rule.

## What ships

One strategy, **`linear`**: the provider cost times a flat markup (`$params['markup']`, default
`1.0`). It is registered when the registry is constructed, so it's always present.

## Adding a strategy

Register a `PricingStrategy` under a name your Plans' component config can refer to:

```php
use Rushing\Commerce\Billing\Pricing\PricingStrategy;
use Rushing\Commerce\Billing\Pricing\PricingStrategyRegistry;

final class PerUnitStrategy implements PricingStrategy
{
    public function price(float $providerCostUsd, float $quantity, array $params): float
    {
        return $quantity * (float) ($params['rate'] ?? 0.0);
    }

    public function consumes(): string
    {
        return 'quantity';
    }
}

$this->app->make(PricingStrategyRegistry::class)->register('per-unit', new PerUnitStrategy);
```

`resolve('per-unit')` returns it, and `names()` lists every registered name. A name nobody registered
throws, because the name comes from stored Plan config and a typo there is a configuration error.

## Duplicates

The [**duplicate-key policy**](/beam/docs/foundations/registries#key-policies) is
**supersede**. Registering `linear` replaces the shipped strategy, so you can change how every
linear meter is priced without touching the components that use it.
